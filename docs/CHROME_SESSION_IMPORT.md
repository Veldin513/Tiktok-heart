# Вход в TikTok через отдельный Chrome

Основной способ создаёт отдельную сессию приложения. Он не копирует вход вашего обычного Chrome и не требует расширений, F12 или cURL.

1. Установите обычный [Google Chrome](https://www.google.com/chrome/), если его ещё нет.
2. В TikTok Heart остановите worker, откройте «Браузер» и выберите нужный профиль приложения.
3. Нажмите «Открыть Chrome для входа». Откроется отдельное окно Chrome на странице сообщений TikTok.
4. Войдите в TikTok вручную. Входить в аккаунт Google и включать синхронизацию Chrome не нужно.
5. Убедитесь, что открываются ваши сообщения, затем закройте именно это отдельное окно. Остальные окна Chrome можно оставить открытыми.
6. Нажмите «Проверить вход» в приложении. Проверка проходит скрыто и ничего не отправляет.
7. Дождитесь сообщения об успешной проверке. Теперь можно запускать worker. Сам он после проверки не запускается.

При первом переходе прежний профиль приложения сохраняется до успешной проверки, затем становится резервной копией. Если проверка не прошла, новый профиль остаётся для следующей ручной попытки, а старый не заменяется. Пока ручной вход не завершён, планировщик и worker не используют этот профиль. Для отказа от перехода закройте отдельный Chrome и нажмите «Отменить незавершённый вход».

При следующей потере авторизации используйте те же кнопки: откроется сохранённый отдельный профиль Google Chrome с прежними данными сайтов. Приложение не создаёт новый профиль на каждый запуск и не обновляет cookies вручную. Отмена повторного входа в уже рабочем Chrome-профиле сохраняет запрет worker до успешной проверки, поскольку сессия могла измениться.

Повседневная работа остаётся скрытой. Вход вручную проходит без Playwright и флагов автоматизации; скрытая проверка и worker используют Playwright с установленным Google Chrome. Это не гарантирует, что TikTok не распознает автоматизацию или не завершит сессию.

Для профиля действует блокировка одновременного запуска: вход, проверка, worker и очистка не должны использовать его одновременно. Очистка сохраняет Service Worker, а в отдельном Chrome-профиле также все cookies и IndexedDB. Повторные попытки после явного выхода останавливаются; резервная копия не может оживить сессию, отозванную TikTok.

Для проверки причины общего выхода держите одинаковое подключение во время ручного входа и работы приложения. Если используете VPN или прокси, не меняйте их между этими шагами. Не запускайте перенос основной сессии параллельно с новым способом. Если проблема повторится, полезно сравнить время последнего запуска и сообщение TikTok в настройках безопасности; полный cURL и cookies для этого не нужны.

Chrome хранит защищённые cookies с привязкой к приложению: [описание Google](https://security.googleblog.com/2024/07/improving-security-of-chrome-cookies-on.html). Поэтому новый профиль продолжает работать именно в Google Chrome, без переноса в Chromium. Отдельный каталог также соответствует [рекомендации Playwright](https://playwright.dev/docs/api/class-browsertype#browser-type-launch-persistent-context).

## Дополнительный способ: перенос существующей сессии через cURL

Этот способ копирует текущую сессию обычного Chrome. При одновременном выходе в приложении, Chrome и на телефоне предпочтительнее отдельный вход выше. Причина такого выхода не установлена: сообщение «Сессия завершена» само по себе её не определяет.

В приложении откройте «Браузер» → «Перенос существующей сессии через cURL» и выберите профиль приложения.

1. В обычном Google Chrome откройте `https://www.tiktok.com/messages`. Сообщения должны открываться с вашим аккаунтом.
2. Нажмите F12, выберите Network (Сеть), обновите страницу Ctrl+R.
3. Найдите строку `messages` с типом `document`. Нажмите правой кнопкой → Copy → Copy as cURL (bash). Обычный Copy as cURL также поддерживается.
4. Вернитесь в приложение, вставьте скопированное в поле «Запрос из Chrome» и нажмите «Проверить и сохранить вход».

Команда не выполняется: приложение читает из неё только cookies. Пароли не нужны. Закрывать Chrome не требуется. Worker нужно остановить на время переноса.

Приложение проверит вход в отдельном профиле тем же Chromium, который используется для работы. Адрес страницы `/messages` сам по себе не считается подтверждением: требуется видимый элемент авторизованного интерфейса TikTok. При успешной проверке создаётся резервная копия прежней авторизации, новая сессия становится рабочей и снимается локальная пауза повторных попыток. Worker автоматически не запускается. При ошибке прежний профиль и пауза сохраняются.

Исходный запрос существует только в памяти и не записывается в файлы или логи. Поле очищается после отправки. Не отправляйте скопированный запрос другим людям: он содержит действующую сессию аккаунта.

Cookies сохраняются в локальном профиле браузера с локальным сроком до 30 дней: скопированный заголовок не содержит исходных сроков хранения. TikTok может завершить сессию раньше. В этом случае повторите перенос свежего запроса. Успешный перенос не гарантирует снятие ограничений, установленных самим TikTok.

Если приложение пишет, что cookies входа отсутствуют, убедитесь, что копируете именно запрос `www.tiktok.com/messages`, а не запрос картинки или другого домена. Если вход не подтверждён, проверьте работу сообщений в Chrome и подключение к TikTok. Приложение не выполняет попыток входа с паролем во время проверки.

Официальная документация Chrome о копировании запросов: <https://developer.chrome.com/docs/devtools/network/reference#copy>.
