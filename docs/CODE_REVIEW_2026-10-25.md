# Проверка кода TikTok Heart — 25 октября 2026

Проверка расширена с присланного патча на подсистемы приложения: Python worker, навигацию и подтверждение доставки, авторизацию и профили, состояние, локальный HTTP API, Telegram, резервные копии, расписание, Windows-лаунчеры, JavaScript и запуск Python из Tauri. Патч целиком не применялся: его основа предшествует отдельному входу Chrome и проверке ответа TikTok о доставке.

Это проверка текущего исходного кода и воспроизводимых сценариев отказа. Она не гарантирует отсутствие остальных ошибок или сохранение сессии на стороне TikTok.

## Исправленные проблемы

| Область | Ошибка и последствия | Исправление и проверка |
| --- | --- | --- |
| Общее состояние | Worker пересобирал JSON из ограниченной модели и терял PID/время запуска Telegram и дополнительные параметры. Параллельные записи могли перетирать изменения друг друга. | Общий read-modify-write защищён системной блокировкой; дополнительные поля сохраняются. Тест конкурентных изменений UI и worker. |
| Запись файлов | Прямая перезапись JSON позволяла читать частичный файл. Временная ошибка доступа могла восприниматься как отсутствие настроек. | Временный файл в той же папке, flush/fsync и атомарная замена. Повтор чтения/замены при Windows sharing violation. Существующий повреждённый конфиг не сбрасывается. Тесты параллельных читателей и повреждения файлов. |
| Блокировки | Удаление lock по возрасту могло лишить живой процесс владения. Между созданием PID-файла и записью PID оставалось окно гонки. | Стабильный отдельный файл и блокировка ОС. RunLock и Telegram используют её вместе с PID-метаданными; файл системной блокировки не удаляется. Проверка другим процессом и освобождение после принудительного завершения владельца. |
| Неопределённая доставка | Неожиданная ошибка или остановка процесса после клика оставляла временную защиту, которая затем истекала. Это допускало повтор фактически доставленного сообщения. | До попытки отправки записывается постоянная защита неопределённой доставки. Она снимается автоматически только при доказанном отсутствии отправки/отказе либо заменяется отметкой подтверждённой доставки. |
| Запись после доставки | TikTok мог подтвердить сообщение, после чего ошибка локального файла или Telegram превращала результат запуска в ошибку без ясного различения доставки и уведомления. | При подтверждённой доставке результат сохраняет `server_ack`; ошибка cooldown оставляет защиту от повтора, ошибка серии сообщается отдельно, ошибка уведомления не меняет доставку. Отдельные тесты для каждого случая. |
| Ошибка адресата | Исключение одного адресата обрывало остальных; ошибка авторизации при поиске чата могла скрываться как «чат не найден». | Ошибки адресата изолированы, ошибки потерянного или непроверенного входа останавливают запуск. Тесты сохранения обоих исключений авторизации. |
| Локальный API | Не проверялись Host/Origin и тип POST. Одной привязки к loopback недостаточно против запросов с посторонних сайтов. | Проверки Host с фактическим портом, same-origin, Sec-Fetch-Site, JSON Content-Type и однозначной длины тела до выполнения обработчика. Socket read timeout. HTTP-тесты через реальный локальный сервер. |
| Telegram-доступ | Пустой список ID разрешал всем управление; меню при старте рассылалось также старым удалённым пользователям. | Пустой список закрывает доступ и запуск; меню получает только текущий список владельцев. ID выбирается пользователем, а не выдаётся первому `/start` автоматически. |
| Telegram-команды | Ошибка обработки обновления оставляла прежний offset и повторяла команду. Повреждённое состояние могло молча сбрасывать offset. Состояние другого токена могло пропускать новые сообщения. | Ошибка конкретного обновления регистрируется без автоматического повторения команды. Повреждённое состояние блокирует запуск. Новые записи состояния привязаны к отпечатку токена. |
| Telegram-настройка | Для создания и изменения настроек требовалось редактировать JSON. Путь файла состояния доверял конфигу. | Мастер BotFather, getMe, просмотр `/start`, выбор ID и редактирование настроек. Сохранение/поиск ID требуют остановленного бота. Путь состояния фиксирован в control. Настройка проверена в скрытом Chromium с подставными ответами Telegram. |
| Секреты | Formatter не защищал строки, записанные прямо в историю и экспорт диагностики. | Маскирование токенов и идентификаторов сессии в логах, JSON-истории, сводке, ответах API и экспорте. Сохранённый токен не возвращается форме. Тест вложенных данных и URL Telegram. |
| Пути профилей | Некоторые точки входа строили путь без общей проверки; `.`/`..`, NTFS-потоки и перенаправления могли выйти за папку профиля. | Общая проверка имени и resolved-пути для worker и UI. Тесты небезопасных имён и Windows-ограничений. |
| Архивы | Windows backslash/NTFS-потоки обходили часть проверок; распаковка и сброс текущих папок происходили до завершения копирования. | Проверки путей, ссылок и размера до глубокой распаковки; предварительная распаковка, замена с сохранением прежних файлов и откат. При ошибке файлы восстановления остаются в backups. Тест искусственного отказа во время замены. |
| Служебные команды | subprocess без предельного времени мог удерживать HTTP-запрос. Один timeout с PIPE не решает наследование дескрипторов дочерним процессом. | Ограниченное ожидание, вывод через временные файлы, остановка дерева процессов по таймауту. Тест с реальным дочерним Python, наследующим вывод. |
| Tauri | Без YARA_PYTHON мог выбираться глобальный Python без зависимостей проекта. | После явного YARA_PYTHON предпочитается `.venv` проекта. Windows-консоль по-прежнему скрыта. |

## Решения по предложенному патчу

- Сохранены последние изменения поиска чата по списку, проверки уникального аккаунта и резервного открытия профиля.
- Сохранены отдельный профиль обычного Chrome, скрытая повседневная работа и требование реального подтверждения сервера TikTok.
- Не перенесено удаление lock-файла по возрасту: это нарушает взаимное исключение у долго работающего процесса.
- Не перенесён PIPE-wrapper с одним `subprocess.run(timeout=...)`: проверен сценарий с наследующим вывод дочерним процессом.
- Ошибки авторизации не скрываются общей изоляцией адресатов.
- Пятиминутный опрос очереди не добавлялся. Настройки задач Windows при этой проверке не изменялись.

## Проверки и их границы

- Полный pytest: **283 passed**, включая существующие тесты навигации, ACK, импорта, восстановления, расписания и Windows-лаунчеров; добавлены тесты отказов и формы Telegram.
- Ruff для исходников/тестов и `node --check` для JavaScript.
- Дополнительный статический анализ Bandit охватил 26 Python-файлов, 9337 строк кода: 0 отметок высокой, 7 средней и 58 низкой важности. Это отметки анализатора, а не число подтверждённых уязвимостей. Отмеченные SQL-запросы строят только фиксированную структуру фильтра с параметризованными доменами; URL-сценарии используют заданные HTTPS-хосты. SHA-1 применяется только к совместимым именам файлов состояния, теперь явно с `usedforsecurity=False`; смена имён сломала бы прежние счётчики.
- Проверка секретов и состава файлов перед публикацией.
- Сборка Tauri и проверка поднятого локального API после перезапуска.

Реальные сообщения при проверке не отправлялись. Ответы Telegram в UI-тесте подставные: получение настоящего токена и `/start` выполняет владелец по инструкции. Длительная работа расписания, реальная доставка следующего сообщения и возможный отзыв сессии TikTok требуют наблюдения при обычном использовании. Программа не может запретить TikTok завершить сессию.

Атомарная замена и откат уменьшают последствия ошибок записи, но не делают восстановление нескольких файлов единой транзакцией при отключении питания. Перед восстановлением создаётся приватная копия; при ошибке staging сохраняется для ручного восстановления.

Токен хранится в локальном конфиге открытым текстом, как и раньше. Маскирование интерфейса и Git-ignore защищают от случайной публикации, но не от программы с доступом к файлам текущего пользователя. Общие backup-архивы авторизации также остаются приватными.

Описание официальных операций Telegram: [BotFather](https://core.telegram.org/bots/features#botfather), [getMe](https://core.telegram.org/bots/api#getme), [getUpdates](https://core.telegram.org/bots/api#getupdates).
