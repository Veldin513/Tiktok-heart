# Changelog

## Unreleased — 2026-10-26

- Исправлены ошибки кнопок Telegram: сбой подтверждения нажатия больше не обрывает навигацию. Просроченное действие запуска или изменения требует свежего нажатия. Журнал сохраняет метод API и причину отказа без токена.
- Повторное открытие неизменившегося меню не создаёт копии сообщений. При включении безопасно обрабатываются все страницы накопленных обновлений, включая очередь длиннее 100 событий.
- В Telegram добавлены понятные инструкции, отмена ввода, возврат в главное меню и страницы профилей/адресатов. Профиль показывает состояние входа и отправки; подтверждённый вход не требует повторной авторизации.
- Администратор добавляет пользователей, назначает и отзывает права кнопками с подтверждением. Личные адресаты, серия, вход и запуск остаются изолированы по владельцу профиля. Старые кнопки с номером строки больше не переключают случайный профиль.
- В приложении разделены кнопки управления Telegram и автоматические итоговые отчёты: прямо указано, что при выключенном управлении кнопки бота не отвечают, а отчёты продолжают приходить.

## Unreleased — 2026-10-25

- Исправлена проверка HTTPS Telegram на Windows: к системному хранилищу добавлены доверенные корневые сертификаты certifi, проверка имени и сертификата остаётся включённой. Добавлен тест настоящего соединения отдельной кнопкой без запуска TikTok.
- Исправлена гонка PID между Windows-лаунчером Python и самим Telegram-ботом: родитель больше не пишет файл владения дочернего процесса и не мешает ему запуститься.
- Итог worker отправляется одним уведомлением после закрытия TikTok. Отдельный постоянный Telegram-процесс для отчёта не нужен; вручную включённое управление остаётся работать. Отчёт различает подтверждение сервера, отказ и неизвестную доставку.
- Добавлены администраторы и личные профили разрешённых Telegram-пользователей с ником и ID. Пользователь управляет своим адресатом, серией, входом и worker; администратор — всеми профилями и доступом. Права проверяются на каждой кнопке и перед сохранением, старые/чужие кнопки не дают обхода.
- Личный worker запускается с выбранным профилем без переключения общего активного профиля; пользователь не может остановить чужой worker. Уведомления профиля получают только его владелец и администраторы.
- Повторное включение Telegram больше не рассылает меню всем чатам. Накопленные запросы меню объединяются, а старые действия не запускаются неожиданно после включения. Добавлена безопасная привязка существующего профиля к Telegram ID без переноса cookies или счётчиков и без удаления папок.

- Добавлены инструкция создания бота через BotFather и настройка Telegram в приложении: проверка токена, поиск личного ID после `/start`, редактирование владельца и доступа. Сохранённый токен не возвращается в интерфейс; изменение настроек требует остановить бота.
- Telegram закрывает доступ при пустом списке владельцев и больше не отправляет панель ранее удалённым пользователям. Ошибка одного входящего обновления не вызывает бесконечное повторение команды.
- Запись общих JSON стала атомарной с системными блокировками между UI, worker и Telegram. Worker сохраняет дополнительные поля управления; повреждённые настройки не заменяются настройками по умолчанию.
- Защита от повторной отправки сохраняется после неожиданной ошибки или остановки процесса. Ошибки записи после подтверждения TikTok и ошибки уведомления Telegram не превращают подтверждённую доставку в неподтверждённый повтор.
- Локальный API проверяет Host, Origin, тип тела POST и источник запроса. Токены и данные входа скрываются в журнале, истории запусков, ответах API и экспорте диагностики.
- Восстановление авторизации сначала распаковывает архив в отдельную папку, проверяет пути и ограничения, затем заменяет файлы с откатом при ошибке. Добавлены запреты обхода Windows-путей, потоков NTFS и ссылок в архиве.
- Служебные команды имеют ограниченное время выполнения и завершают дерево процессов при таймауте. Tauri предпочитает Python из проектной `.venv`.
- Добавлены проверки конкуренции, аварийной отправки, ограничений API, отката восстановления и формы Telegram в скрытом браузере. Подробности — [проверка кода](docs/CODE_REVIEW_2026-10-25.md).

## Unreleased — 2026-10-24

- Устранён ложный успех после Enter: счётчик серии и пауза обновляются только после ответа сервера TikTok с идентификатором отправленного сообщения. HTTP и WebSocket наблюдаются пассивно; неизвестный протокол, отказ или отсутствие ответа не считаются успехом.
- Неоднозначная отправка блокирует повтор этому адресату до проверки чата и явного разрешения в интерфейсе. Тестовый режим больше не записывает сообщение как отправленное; прежние записи без подтверждения помечаются отдельно.
- Тайм-аут страницы больше не приравнивается к подтверждённому выходу из аккаунта. Уточнено точное сопоставление имён адресатов.
- Исправлены скачки готовности между 98 и 100: необязательный Telegram больше не снижает балл. Интерфейс использует оценку полной локальной диагностики; до её получения отображается расчёт без выдуманного процента.
- Исправлено согласование 12-часового расписания с паузой адресата: следующий запуск привязывается к фактической отправке, включая ручные запуски. Частые фоновые проверки очереди не добавляются. Меняется только время существующего триггера, настройки автозапуска сохраняются.
- Плановый запуск пропускает паузу, требование нового входа, активный импорт и auth backoff до открытия браузера. Исправлена настройка прав текущего пользователя на задачи приложения; ошибка сохранения объясняет разовый шаг с правами администратора для старых задач.
- Усилено скрытие явного признака webdriver штатными параметрами Chromium. Скрытый режим работы сохранён; версия браузера, языки и плагины не подменяются.
- Блок переименован в «Готовность к запуску»: различаются наличие cookies, результат последней проверки и требование повторного входа. Полная и быстрая проверки используют одинаковые признаки; изменение сессии обновляет полную оценку.
- Отсутствие Local State или Preferences само по себе больше не считается блокером. Неизвестный результат входа отображается как информация; подтверждённый отказ входа остаётся блокером и ограничивает балл готовности.
- Исправлена обработка логов: success_count=0 больше не считается успешным событием, новая ошибка не скрывается старым успехом.

## 2.2.0 — 2026-10-15

### Исправления запуска по расписанию

- Сохранённый PID проверяется по пути скрипта и времени создания процесса. Если Windows выдала старый номер другой программе, новый запуск больше не пропускается.
- Блокировка профиля восстанавливается, если указанный в ней PID был повторно использован после завершения worker или перезагрузки.
- При завершении worker очищает собственный PID. Блокировка освобождается даже при ошибке очистки состояния.
- Команда остановки проверяет принадлежность процесса worker перед завершением.
- Флаг остановки сбрасывается до запуска дочернего процесса, чтобы новый worker не прочитал старую команду остановки.
- Тихий launcher переводит параметры `--boot-force`, `--self-test` и `--no-browser` в соответствующие переключатели PowerShell.

### Другие изменения

- Включены накопленные изменения интерфейса, истории запусков, диагностики и управления расписанием.
- Добавлены проверка и восстановление backup авторизации с предварительной резервной копией.
- Разделены службы резервных копий, производительности и расписания; удалён устаревший интерфейс.
- Согласованы версии Python-проекта, Node-пакета и Tauri. Зависимости для проверки кода теперь включают Ruff.

Обновление выполняется в существующей папке проекта. Локальные профили, cookies, токены, логи и резервные копии не входят в публикацию.
