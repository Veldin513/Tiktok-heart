# Защита профилей

Ключ создаётся на компьютере владельца, отдельно от исходников. Публикация приложения в GitHub не публикует ключ. Обновления не заменяют его; при потере ключа зашифрованные данные не пересоздаются как пустой профиль.

Файлы браузера и его внутренние копии сохраняются в `browser.heart-vault`. Настройки профилей с адресатами и управляемые архивы входа также шифруются. Используется AES-256-GCM с новым случайным nonce для каждой записи. Архив проверяется до удаления открытых файлов, а при восстановлении — до извлечения. Ошибка проверки сохраняет исходные данные. [Документация cryptography](https://cryptography.io/en/stable/hazmat/primitives/symmetric-encryption/).

Личный ключ и локальная копия фразы хранятся в `%LOCALAPPDATA%\TikTokHeart\Keys` под защитой Windows DPAPI для текущего пользователя. Это защищает данные при копировании файлов отдельно от учётной записи, но не скрывает ключ от процесса, уже работающего с правами владельца или с полным контролем над ПК. [Документация Microsoft](https://learn.microsoft.com/en-us/windows/win32/SecCrypto/example-c-program-using-cryptprotectdata).

Для другой установки Windows нужны файл `.heart-recovery` и секретная фраза. Фраза содержит 192 случайных бита; для ключа восстановления применяется scrypt с параметрами N=131072, r=8, p=1. Файл сам по себе не открывает ключ. Ключ и фраза не отправляются в Telegram, не записываются в журналы, не включаются в диагностику. Фраза показывается только по отдельному локальному действию и очищается при выходе из раздела.

Браузер временно работает с открытыми файлами своего профиля. После нормального закрытия они защищаются снова. Если процесс оборвался, журнал восстановления сохраняет более новое рабочее состояние и позволяет завершить защиту при следующем запуске. После аварии или отключения питания открытые рабочие файлы могут оставаться на диске до следующего запуска. Шифрование не означает гарантированного физического стирания прежних копий с диска.

Журналы, счётчики, вручную сделанные копии папки и сторонние архивы не входят в эту защиту. У управляемых архивов в `backups/auth` сохраняется расширение `.zip`, но при включённой защите их содержимое зашифровано: открывайте и восстанавливайте их через приложение.

Восстановление собственного ключа не переносит внутренние ключи Google Chrome между установками Windows и не отменяет решения TikTok о завершении сессии. После такой переустановки может потребоваться снова войти в TikTok.
