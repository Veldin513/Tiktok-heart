# Установка TikTok Heart с нуля

Инструкция для человека, который раньше не устанавливал программы из GitHub. Ничего программировать или менять в коде не нужно.

Для обычного компьютера с **Windows 10/11, 64 bit (Intel/AMD)**. Для ARM-компьютеров понадобятся другие установщики, этот вариант здесь не описан.

Приложение состоит из окна управления и worker — программы, которая работает с TikTok. Сначала установим нужные компоненты, затем один раз соберём окно приложения и перенесём вход из Chrome.

> Если приложение у вас уже работает, переустанавливать всё не нужно. Для повторного входа перейдите к разделу 9, для обновления — к разделу 12.

## Как пользоваться инструкцией

- Проходите разделы по порядку.
- Текст в серых блоках — команды. Копируйте команду целиком, вставляйте в PowerShell и нажимайте Enter.
- Не копируйте тройные обратные кавычки вокруг блоков и строку приглашения вида `PS ...>`.
- Следующую команду выполняйте, когда снова появилась строка `PS ...>`.
- Если команда закончилась ошибкой, сначала найдите её в разделе 13. Не продолжайте установку вслепую.
- Команды нужны только при установке и обновлении. Для ежедневного запуска будет обычный файл.

## 1. Скачайте и распакуйте проект

1. Откройте [репозиторий TikTok Heart](https://github.com/Veldin513/Tiktok-heart).
2. Нажмите зелёную кнопку **Code**, затем **Download ZIP**.
3. В папке «Загрузки» нажмите на скачанном ZIP правой кнопкой → **Извлечь всё**.
4. Откройте распакованную папку. Если внутри лежит ещё одна папка `Tiktok-heart-main`, откройте её.
5. Найдите файлы **start_app.bat**, **start_app.vbs**, **requirements.txt** и папки **yara_app**, **src-tauri**. Именно эта папка нужна дальше.
6. Переместите всю эту папку в постоянное место, например в «Документы». Работайте с распакованной копией.

Не вытаскивайте один файл запуска из папки: ему нужны остальные файлы проекта. После настройки расписания папку не перемещайте без повторной регистрации задач.

## 2. Установите Python

Python запускает рабочую часть приложения.

1. Откройте [страницу Python для Windows](https://www.python.org/downloads/windows/).
2. Найдите стабильный выпуск **Python 3.14.x** и ссылку **Windows installer (64-bit)**. Эта ветка проверена при развёртывании проекта.
3. Скачайте и запустите установщик. Для этой инструкции выбирайте обычный installer, а не **embeddable package**, архив исходников или MSIX.
4. Если на первом экране есть **Add python.exe to PATH**, поставьте галочку.
5. Выберите **Install Now**. Оставьте включённым Python Launcher, если установщик предлагает его отдельно.
6. Дождитесь завершения и закройте установщик.

Если установка только для текущего пользователя заканчивается ошибкой, повторите через **Customize installation → Install for all users**, если такой пункт доступен и у вас есть права администратора.

## 3. Установите Node.js

Node.js нужен для подготовки окна приложения.

1. Откройте [страницу загрузки Node.js](https://nodejs.org/en/download).
2. Выберите **LTS**, **Windows**, **x64**, **Installer (.msi)**.
3. Запустите скачанный файл.
4. Нажимайте **Next**, примите лицензию, оставьте стандартные компоненты, включая npm.
5. Нажмите **Install** и дождитесь окончания.

Дополнительные инструменты сборки через Chocolatey на этом этапе не нужны: необходимые инструменты Microsoft установим отдельно.

## 4. Установите инструменты Microsoft и Rust

Они нужны для первой сборки окна Tauri.

### 4.1. C++ Build Tools

1. Откройте [Microsoft C++ Build Tools](https://visualstudio.microsoft.com/visual-cpp-build-tools/).
2. Скачайте и запустите установщик **Build Tools**.
3. В списке рабочих нагрузок выберите **Desktop development with C++** / **Разработка классических приложений на C++**.
4. В выбранных компонентах должны быть инструменты **MSVC для x64/x86** и **Windows SDK**. Оставьте стандартные компоненты этой рабочей нагрузки.
5. Нажмите **Install / Установить**. Загрузка может быть большой; дождитесь завершения.
6. Если Windows просит перезагрузку, перезагрузите компьютер.

Устанавливать полную среду Visual Studio для редактирования кода не требуется.

### 4.2. Rust

1. Откройте [официальную страницу установки Rust](https://rust-lang.org/tools/install/).
2. Скачайте **rustup-init.exe (x64)** для Windows.
3. Запустите файл. Если открылось окно с выбором установки, выберите **Proceed with standard installation** — обычно пункт **1**, затем Enter.
4. Дождитесь окончания и закройте окно.

Используйте стандартный Windows MSVC-вариант установки Rust.

### 4.3. WebView2

WebView2 отображает интерфейс приложения. Если он уже установлен, повторять установку не требуется.

При необходимости откройте [Microsoft Edge WebView2](https://developer.microsoft.com/microsoft-edge/webview2/), найдите **Evergreen Runtime**, скачайте установщик **x64** и выполните установку.

Требования к компонентам Windows можно сверить с [официальной документацией Tauri](https://v2.tauri.app/start/prerequisites/#windows).

## 5. Откройте PowerShell в папке проекта

После установки Python, Node.js и Rust **закройте старые окна терминала**: они могли не получить новые пути к программам.

1. Откройте в Проводнике папку проекта, в которой лежит `start_app.vbs`.
2. Нажмите на адресную строку Проводника.
3. Вместо пути введите `powershell` и нажмите Enter.
4. Откроется PowerShell. Адрес после `PS` должен указывать на папку проекта.

Для проверки введите:

```powershell
Test-Path .\start_app.vbs
```

**Ожидаемый результат: `True`.** Если получилось `False`, вы открыли другую папку. Закройте PowerShell и повторите этот раздел.

Теперь проверяйте инструменты, по одной команде:

```powershell
py -3.14 --version
```

Должно появиться `Python 3.14.x`.

```powershell
node --version
```

Должен появиться номер версии Node.js.

```powershell
npm.cmd --version
```

Должен появиться номер версии npm.

```powershell
cargo --version
```

Должна появиться версия Cargo — инструмента сборки Rust.

Если какая-то команда «не распознана», откройте новый PowerShell после установки соответствующей программы. Если это не помогло, переустановите недостающий компонент. К сборке пока не переходите.

## 6. Установите Python-зависимости и Chromium

Все следующие команды выполняйте в том PowerShell, который открыт в папке проекта.

### 6.1. Создайте отдельное окружение приложения

```powershell
py -3.14 -m venv .venv
```

Команда создаст папку `.venv` и может завершиться без сообщений — это нормально.

### 6.2. Обновите установщик Python-пакетов

```powershell
.\.venv\Scripts\python.exe -m pip install --upgrade pip
```

### 6.3. Установите рабочие зависимости

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt -r requirements-desktop.txt
```

Дождитесь завершения. Сообщения о загрузке пакетов и `Successfully installed` нормальны.

### 6.4. Проверьте установку

```powershell
.\.venv\Scripts\python.exe -c "import playwright, requests, psutil; print('Dependencies OK')"
```

**Ожидаемый результат: `Dependencies OK`.**

### 6.5. Укажите папку для рабочего браузера

```powershell
$env:PLAYWRIGHT_BROWSERS_PATH = Join-Path $PWD '.playwright-browsers'
```

Команда может ничего не вывести — это нормально.

### 6.6. Скачайте Chromium

```powershell
.\.venv\Scripts\python.exe -m playwright install chromium
```

Дождитесь завершения загрузки. Появится папка `.playwright-browsers`.

Это отдельный Chromium для worker. Даже если Google Chrome установлен, этот шаг нужен. Размещение браузера в папке проекта также помогает избежать встречавшихся ошибок запуска из AppData.

Активировать `.venv` отдельной командой не нужно: в инструкции уже указан точный путь к Python.

## 7. Один раз соберите окно приложения

### 7.1. Установите Node-зависимости

```powershell
npm.cmd ci
```

Появится папка `node_modules`. Предупреждение npm само по себе не означает ошибку; команда должна завершиться без `npm error`.

### 7.2. Укажите Python для сборки и запуска

```powershell
$env:YARA_PYTHON = (Resolve-Path '.\.venv\Scripts\python.exe').Path
```

### 7.3. Выполните сборку

```powershell
npm.cmd run build -- --no-bundle
```

Первая сборка может идти долго и скачивать дополнительные пакеты. Не закрывайте окно, пока не вернулась строка `PS ...>`. Эта команда собирает приложение без отдельного MSI-установщика.

### 7.4. Проверьте результат

```powershell
Test-Path .\src-tauri\target\release\yara-control.exe
```

**Ожидаемый результат: `True`.** Если `False`, сборка не закончилась успешно — найдите ошибку в разделе 13.

Не переносите один этот exe в другую папку: приложению нужны исходники, Python и локальные данные проекта.

## 8. Откройте приложение без cmd

В Проводнике дважды щёлкните файл **start_app.vbs**.

Также можно выполнить:

```powershell
wscript.exe .\start_app.vbs
```

**Ожидаемый результат:** открывается окно **TikTok Heart**, отдельное окно cmd не остаётся.

Команду из блока вводят в PowerShell. Вставлять её в содержимое `start_app.vbs` не нужно.

Для удобства можно нажать на `start_app.vbs` правой кнопкой → **Создать ярлык** и переместить ярлык на рабочий стол. Сам файл и папку проекта оставьте на месте.

Если окно не открылось, попробуйте `start_app.bat` и раздел 13. Тесты и регистрацию расписания для первого открытия выполнять не требуется.

## 9. Перенесите вход в TikTok из Chrome

Если нужен новый профиль, сначала откройте в приложении **«Профили»**. Введите название (например, `main`) и нажмите **«Создать профиль»**. Выберите его в списке. Справа добавьте имя собеседника из чатов и ссылку `https://www.tiktok.com/@username` либо `@username`, затем нажмите **«Добавить адресата»**. Кнопка **«Перенести вход для этого профиля»** откроет импорт с уже выбранным профилем. Для работы с ним нажмите **«Использовать»** в карточке профиля. Изменять профили и адресатов нужно при остановленном worker.

Если TikTok блокирует вход в рабочем Chromium, входите в **обычном Google Chrome**, затем переносите готовую сессию.

1. Откройте обычный Chrome и войдите в свой аккаунт TikTok.
2. Перейдите на [страницу сообщений TikTok](https://www.tiktok.com/messages). Убедитесь, что сообщения открываются без просьбы войти.
3. Нажмите **F12**. Если на ноутбуке эта клавиша управляет громкостью или яркостью, попробуйте **Fn+F12** или **Ctrl+Shift+I**.
4. В появившейся панели откройте **Network / Сеть**. Если вкладка скрыта, найдите её за кнопкой `»`.
5. Нажмите **Ctrl+R**, чтобы обновить страницу и заполнить список запросов.
6. Найдите строку **messages**, у которой тип **document**. Это основной запрос страницы. Нажмите на ней правой кнопкой.
7. Выберите **Copy → Copy as cURL (bash)**. Если есть только **Copy as cURL**, выберите его. Не выбирайте **Copy all as cURL**.
8. Вернитесь в TikTok Heart. Остановите worker, если он запущен.
9. Откройте **«Браузер» → «Импорт из Chrome»**.
10. Выберите профиль приложения, с которым будете работать. Для первой установки обычно это `default`.
11. Нажмите на поле **«Запрос из Chrome»** и вставьте скопированное через Ctrl+V.
12. Нажмите **«Проверить и сохранить вход»**. Подождите результата, обычно до 90 секунд.

**Ожидаемый результат:** сообщение об успешном переносе. Поле с запросом очищается. Worker автоматически не запускается.

Запрос содержит данные доступа к аккаунту. Вставляйте его только в поле приложения. Не отправляйте его в GitHub, чат или другим людям. Приложение не запускает эту команду — оно извлекает cookies и проверяет их в отдельном Chromium.

Chrome закрывать не нужно. Старое копирование папки Chrome для современных защищённых cookies `v20` не подходит.

### Если авторизация позже пропадёт

После потери входа или появления проверки TikTok worker прекращает работу. Следующие запуски не открывают браузер и не запускают повторный вход. В разделе «Браузер» появится указание на необходимость свежего переноса. Ограничение снимается только после успешного импорта новой сессии. При нечитаемом ключе cookies профиль автоматически не сбрасывается.

Это защищает от лишних обращений и локального сброса профиля, но не гарантирует, что TikTok не завершит сессию. Импорт и worker используют одинаковые настройки рабочего Chromium; приложение не подменяет `navigator`, список плагинов и языки браузера. Если выход произошёл одновременно в Chrome и приложении, проверьте устройства и события безопасности аккаунта: [инструкция TikTok](https://support.tiktok.com/en/safety-hc/account-and-user-safety/account-safety).

Chromium по-прежнему работает скрыто, без окна. Приложение уменьшает явные признаки webdriver через параметры запуска, сохраняя штатные версию браузера, языки и плагины. Это не гарантирует незаметность автоматизации или сохранение сессии TikTok.

**Готовность к запуску** оценивает локальные настройки и показывает результат последней проверки входа. Это не непрерывная проверка TikTok: наличие файла Cookies не доказывает действующую авторизацию. Результат проверки сохраняется без cookies. Отсутствие `Local State` или `Preferences` само по себе не считается блокером и не требует повторного импорта работающего входа. Если результата проверки ещё нет, отображается информационный статус «Вход не проверен». После фактического отказа входа worker останавливает повторные попытки до свежего подтверждённого импорта.

### Если журнал показывает отправку, а сообщения нет

Новая версия считает успехом только ответ сервера TikTok с идентификатором именно отправленного сообщения. Это подтверждает приём сообщения TikTok, но не прочтение адресатом. Простое нажатие Enter и очистка поля ввода больше не считаются успехом. Старые записи без такого подтверждения не являются доказательством отправки.

Если ответ не получен, в разделе **«Профили»** у адресата появится **«не подтверждено»**. Пауза отправки и серия не увеличиваются, автоматическое повторение этому адресату блокируется. Сначала проверьте чат в TikTok. Если сообщения действительно нет, нажмите **«Разрешить новую попытку»**. Сама кнопка сообщение не отправляет.

Тайм-аут или неполная загрузка страницы считаются неопределённой проверкой, а не доказательством выхода. Если вход одновременно пропал и в Chrome, и на телефоне, причина общего завершения сессий требует отдельной проверки: усиление маскировки не гарантирует её устранение. Повторный перенос основной сессии без выяснения причины может повторить проблему.

Повторите этот раздел со свежим запросом. Переустанавливать приложение не нужно. Повторять перенос при каждом запуске тоже не нужно.

Приложение хранит перенесённую сессию, но TikTok может её завершить. Автоматическое получение новой сессии без участия пользователя не реализовано. При неудачном импорте прежний профиль сохраняется.

Подробнее: [перенос авторизации](docs/CHROME_SESSION_IMPORT.md).

## 10. Настройте работу

1. Выберите активный профиль.
2. Добавьте своих адресатов и нужные сообщения в интерфейсе приложения.
3. Включите **dry_run** — режим пробного запуска без реальной отправки.
4. Выполните **self-test / самопроверку** и прочитайте результат и журнал.
5. Когда настройки проверены и вы хотите включить реальную отправку, отключите dry_run.
6. Нажмите запуск worker.

Успешная самопроверка ещё не доказывает успешную отправку сообщения. Сначала проверяйте небольшой объём работы и журнал результатов.

Для первого запуска не требуется вручную создавать JSON-файлы, редактировать исходники или настраивать Telegram.

## 11. Включите расписание — по желанию

Настраивайте расписание после проверки входа и адресатов.

В приложении откройте управление расписанием. Предусмотрены запуск при входе в Windows с задержкой две минуты и повтор каждые 12 часов. После завершения отправки программа один раз согласует время следующего запуска с паузой адресата. Это учитывает и ручные запуски. Если плановый запуск оказался раньше окончания паузы, он переносится на время готовности адресата. Частых фоновых проверок очереди нет. Запуск при входе в Windows сохраняет отдельно предусмотренное исключение из паузы.

После обновления со старой версии один раз пересохраните расписание. Если Windows пишет «Отказано в доступе», закройте TikTok Heart, нажмите правой кнопкой на `scripts/windows/register_worker_schedule.bat` и выберите **«Запуск от имени администратора»**. Скрипт даст вашему пользователю право изменять только задачи приложения; настройки запуска worker останутся без повышения привилегий. После успешной регистрации запускайте приложение обычным способом. Worker меняет только время существующего повторного триггера, сохраняя настройки автозапуска.

Проверьте, что задачи включены и указывают на текущую папку проекта. Работа требует включённого ПК и входа пользователя в Windows. Пробуждение ПК выключено; пропущенный запуск разрешён после возобновления работы. Если интернет или TikTok недоступны, отправка может задержаться. Требование повторного входа не снимается расписанием.

Если используете скрипт, из папки проекта выполните:

```powershell
.\scripts\windows\register_worker_schedule.bat
```

Если Windows сообщает о нехватке прав при регистрации задач, повторите этот шаг в PowerShell с нужными правами. Если открываете другой терминал, сначала перейдите в папку проекта.

Удаление расписания:

```powershell
.\scripts\windows\unregister_worker_schedule.bat
```

После перемещения папки проекта зарегистрируйте задачи заново.

## 12. Как обновить приложение

1. Остановите worker и закройте окно TikTok Heart.
2. Через приложение заранее создайте резервную копию авторизации. Храните её приватно.
3. Сохраните отдельную копию своих папок `control` и `profiles`. Там находятся настройки и вход.
4. Скачайте новый ZIP из GitHub и распакуйте его отдельно.
5. Скопируйте обновлённые исходники в прежнюю папку проекта. Сохраните свои `control`, `profiles`, `logs`, `backups` и локальные секреты; не заменяйте их примерами. Не распаковывайте новую папку проекта внутрь старой.
6. Откройте PowerShell в прежней папке проекта, как в разделе 5.
7. Повторите раздел 6 начиная с обновления pip, затем раздел 7. Пересборка после обновления также применит исправления окна и тихого запуска.
8. Запустите `start_app.vbs`. Если вход сохранился, переносить его заново не требуется.

При обновлении Playwright обязательно повторите скачивание Chromium. Если PowerShell был закрыт, сначала снова задайте `PLAYWRIGHT_BROWSERS_PATH`, как в пункте 6.5.

Если вы установили проект через Git и не меняли его исходники, вместо скачивания ZIP можно выполнить `git pull --ff-only` в папке проекта, затем обновить зависимости и пересобрать приложение.

## 13. Если что-то не получилось

| Что видите | Что сделать |
| --- | --- |
| `Test-Path .\start_app.vbs` возвращает `False` | Откройте правильную распакованную папку: внутри должны лежать `start_app.vbs` и `requirements.txt`. |
| Python открывает Microsoft Store | Вернитесь к разделу 2 и установите обычный Python installer. |
| `py -3.14` не находит Python | Проверьте, что установлен Python 3.14, откройте новый PowerShell. Если установлен другой поддерживаемый Python 3.12+, можно создать окружение через `python -m venv .venv`, предварительно проверив `python --version`. |
| `node`, `npm.cmd` или `cargo` «не распознаны» | Закройте и откройте PowerShell после установки инструментов. Если не помогло, проверьте установку соответствующей программы. |
| `npm.ps1 cannot be loaded` | Используйте именно `npm.cmd`, как в инструкции. Политику выполнения PowerShell менять не нужно. |
| `ModuleNotFoundError` | Повторите пункт 6.3. Если ранее вручную задавали `YARA_PYTHON`, убедитесь, что он указывает на Python из проектной `.venv`. |
| `link.exe` или Windows SDK не найдены | В Visual Studio Installer добавьте C++ workload и Windows SDK из пункта 4.1, затем откройте новый PowerShell и повторите сборку. |
| Chromium: `Executable doesn't exist` | Повторите пункты 6.5–6.6 в одном PowerShell. |
| Chromium: `spawn UNKNOWN` / SideBySide | Повторите установку в проектную `.playwright-browsers`. Это устранило проблему в проверенной установке; возможны и другие причины. |
| Рядом с приложением остаётся cmd | Обновите файлы и пересоберите приложение по разделу 7. Затем запускайте `start_app.vbs`. В актуальной debug-сборке консоль также отключена. |
| Пустое окно или приложение закрывается | Проверьте WebView2. Для диагностики запустите `.\scripts\windows\start_app_shell.bat`: он должен открыть локальный интерфейс в браузере. Это проверка Python-части, а не замена сборки Tauri. |
| TikTok запрещает вход в Chromium | Используйте перенос из обычного Chrome по разделу 9. |
| Сообщение про cookies `v20` или ключ шифрования | Выбран старый способ копирования профиля. Используйте поле «Запрос из Chrome». |
| В запросе нет cookies входа | Скопируйте основной `messages` с типом `document` из Chrome, в котором уже открыты ваши сообщения. |
| Вход после импорта не подтверждён | Проверьте, что сообщения открываются в Chrome, проверьте подключение и повторите перенос свежего запроса. Это не всегда означает ошибку установки: возможны ограничения TikTok. |
| Worker не отправляет сообщения | Проверьте dry_run, активный профиль, адресатов, паузы, расписание и журнал worker. |

Если ошибка осталась, сохраните **текст ошибки и название шага**, на котором она появилась. Перед публикацией скриншотов или журналов уберите данные аккаунта, cookies и токены. Для обращения за помощью не нужен полный cURL-запрос с авторизацией.

## Что хранится в папке проекта

- `.venv` — Python и установленные для приложения пакеты.
- `.playwright-browsers` — рабочий Chromium.
- `node_modules` — компоненты подготовки интерфейса.
- `src-tauri/target` — результат сборки окна приложения.
- `control` — ваши локальные настройки.
- `profiles` — профили браузера и данные входа.
- `logs` — журналы работы.
- `backups` — резервные копии.

Не удаляйте эти папки ради обновления и не публикуйте профили, cookies, токены или архивы авторизации. Всё это остаётся на вашем компьютере.
